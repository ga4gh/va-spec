Base Profiles
!!!!!!!!!!!!!

VA Profiles represent specializations of generic VA Core model classes that have been extended and/or constrained to represent a particular type of knowledge. At present, profiles can be built on four VA core classes: 

 - **Proposition Profiles** provide abstract representations of specific kinds of possible facts in a domain of discourse, which may or may not be true (e.g. a ``VariantPathogenicityProposition`` may express the possible fact that *"HRAS:c.173C>T causes Costello Syndrome"*)
 - **Statement Profiles** report assertions by particular agents that a specific type of Proposition is true or false, or report an overall level of confidence or evidence for or against a Proposition for which a definitive assertion cannot yet be made (e.g. a ``VariantPathogenicityStatement`` may report the definitive classification of HRAS:c.173C>T as pathogenic, as made by ClinGen curators using a specific set of evidence).
 - **Evidence Line Profiles** report how collection of specific kinds of information are interpreted as evidence supporting or disputing a specific kind of Proposition that may ultimately be asserted about a variant (e.g. an ``AlleleFrequencyPathogenicityEvidenceLine`` may report that data from an allele frequency analysis provide moderate support for the pathogenicity of HRAS:c.173C>T).
 - **Study Result Profiles** are used to describe collections of a specific type of data about a variant that is generated in a particular study or analysis, and may be used as evidence for higher order assertions (e.g. a ``CohortAlleleFrequencytStudyResult`` may capture various allele frequency data items about HRAS:c.173C>T along with shared provenance information, which may be interpreted as evidence for this variant's pathogenicity).

In the current iteration of the VA-Spec, we distinguish between two categories of profiles:

- **Base Profiles**:  Specialize generic VA core classes with domain-specific constraints through formal definition of concrete subclasses.  In the current iteration of the VA Spec, the Base Profiling approach is used to create **Study Result** and **Proposition** profiles, which can be used/referenced within  Statement and Evidence Line community profiles.
- **Community Profiles**: Layers additional constraints on VA core classes using a mechanism that does not create concrete subclasses, to enforce adherence to formal terminology and curation conventions established in a specific community of practice (e.g. the ACMG 2015 guidelines for variant pathogenicity interpretation).   In the current iteration of the VA Spec, this constraint-based mechanism approach is used to create **Statement** and **Evidence Line** Profiles that build on these core classes. 

.. note::  The technical rationale and basis for these distinctions is not important at this point in time. At the end of the day these all represent specializations of VA core classes that can be used on their own or together, to represent the meaning and provenance of knowledge about genetic variation. As the VA-Spec matures, the rationale and implementation for how profiles are defined and organized will evolve to provide a more user friendly framework for community-driven development. 

All VA Profiles are authored as yaml-based information models, from which web documentation and a formal json schema are automatically generated by `GKS Metaschema Tooling <https://github.com/ga4gh/gks-metaschema>`_.  The editable **yaml source files** in which profiles are defined, as well as derived machine-readable **JSON schema** for each Profile can be found in the directories `here <https://github.com/ga4gh/va-spec/tree/1.x/schema/va-spec>`_. Web **documentation** about each Base Profile can be found in the pages linked below.
